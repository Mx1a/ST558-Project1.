Making a Function to get the dictionary

The project wants one list per year (2021 to 2024), and the only thing that changes between years is the year inside the URL. This means I need to build a function that can build the URL differently for each year. The paste0() function can be used for this so that only the year can be changed in the URL. The argument for my function is the year since its the only changing variable. I then can use all my previous code chunks just renamed to a more general form to extract the information from any given year that is run to the function. In essence the function will take a year argument then will builds the URL with paste0() runs my steps, and return a vars_all_values list. The wanted_vars can stay outside the function since it’s the same for every year.

wanted_vars <- c("AGEP","GASP","GRPIP","JWAP","JWDP","JWMNP","PWGTP","FER","HHL","SCH","SCHL","SEX","ST","STATE","REGION","DIVISION")

get_var_values <- function(year) {
  url <-  paste0("https://api.census.gov/data/",
                 year,
                 "/acs/acs1/pums/variables.json")
  variables_m <- GET(url)
  vars_all <- fromJSON(content(variables_m, "text"))
  vars_to_keep <- wanted_vars[wanted_vars %in% names(vars_all$variables)]
  vars_all_sub <- vars_all$variables[vars_to_keep]
  vars_all_values <- lapply(vars_all_sub, function(x)
    x$values)
  return(vars_all_values)
}

Next I turn these steps into a helper function, helper_tibble(), that takes the response from GET() and returns a tibble. Keeping this separate from the main query function means the query function only has to build the URL and request the data, and it can hand the response to this helper every time.

helper_tibble <- function(resp) {
  parsed_data <- fromJSON(content(resp,"text"))
  col_names <- parsed_data[1, ]
  colnames(parsed_data) <- col_names
  data_tibble <- as_tibble(parsed_data[-1,])
  return(data_tibble)
}

Building a query function to handle year and filter requirements

The variables of the function will be year (default 2024), the numeric variables (default c(“AGEP”, “PWGTP”)), the categorical variables (default “SEX”), the geography level (default “State”), the specific region/division/state to subset on (default is NC which is state 37).In order for this to work we will have to test each layer before moving on to the next, so if something breaks, we know where the issue is and can fix it.

get_census_data <- function(year = 2024,
                             num_vars = c("AGEP", "PWGTP"),
                             cat_vars = "SEX",
                             geo_level = "State",
                             geo_subset = NULL) { 
  
  vars_string <- paste(c(num_vars, cat_vars), collapse = ",")
  url <- paste0("https://api.census.gov/data/",
              year,
              "/acs/acs1/pums?get=",
              vars_string,
              "&for=state:37&key=",
              api_key) 
  
  data_rsp <- GET(url)
  data_all_tibble <- helper_tibble(data_rsp)
  return(data_all_tibble)
}

Adding the geography layer to the function :

Next I add the geography arguments. The user can choose one geography level (Region, Division, or State) and which specific area to pull data for. If no area is given, the function defaults to North Carolina, or the division and region that include it, which keeps the default query small and fast. The function also checks that the area codes are valid using the variable values I saved earlier in the .rds file, and the user can enter “all” to get every area at that level.

 get_census_data <- function(year = 2024,
                             num_vars = c("AGEP", "PWGTP"),
                             cat_vars = "SEX",
                             geo_level = "State",
                             geo_subset = NULL) { 
  
### check that a single valid year was given##############################
  if (length(year) != 1) {
    stop("you can only give one year at a time")
  }
  if (!(year %in% 2021:2024)) {
    stop("year must be 2021, 2022, 2023, or 2024")
  }
  
###check numeric variables################################################
   allowed_num_vars <- c("AGEP", "GASP", "GRPIP", "JWAP", "JWDP", "JWMNP", "PWGTP")
  
   if (!all(num_vars %in% allowed_num_vars)) {
    stop(paste("numeric variables must be from:",
               paste(allowed_num_vars, collapse = ", ")))
  }
  if (!("PWGTP" %in% num_vars)) {
    stop("PWGTP must always be included")
  }
  if (length(setdiff(num_vars, "PWGTP")) < 1) {
    stop("you must include at least one numeric variable besides PWGTP")
  }
  
###check categorical variables###########################################
  allowed_cat_vars <- c("FER", "HHL", "SCH", "SCHL", "SEX") 
  
  if (length(cat_vars) < 1) {
    stop("you must include at least one categorical variable")
  }
  if (!all(cat_vars %in% allowed_cat_vars)) {
    stop(paste("categorical variables must be from:",
               paste(allowed_cat_vars, collapse = ", ")))
  }

 ### check geography level ###
  allowed_geo_levels <- c("Region", "Division", "State")

  if (length(geo_level) != 1) {
    stop("you can only choose one geography level")
  }
  if (!(geo_level %in% allowed_geo_levels)) {
    stop(paste("geo_level must be one of:",
               paste(allowed_geo_levels, collapse = ", ")))
  }

  ### set default subset if none given (NC and the areas it belongs to) ###
  if (is.null(geo_subset)) {
    if (geo_level == "State") {
      geo_subset <- "37"
    } else if (geo_level == "Division") {
      geo_subset <- "5"
    } else {
      geo_subset <- "3"
    }
  }

  ### check subset values against the saved variable values ###
  var_values <- readRDS("data/comb_list.rds")[[as.character(year)]]

  if (geo_level == "State") {
    geo_var <- ifelse("STATE" %in% names(var_values), "STATE", "ST")
  } else {
    geo_var <- toupper(geo_level)
  }
  allowed_codes <- names(var_values[[geo_var]]$item)

  if (!(length(geo_subset) == 1 && tolower(geo_subset) == "all")) {
    if (!all(geo_subset %in% allowed_codes)) {
      stop(paste("invalid", geo_level, "code. Allowed codes are:",
                 paste(allowed_codes, collapse = ", ")))
    }
  }

  ### turn the subset into the URL format ###
  if (length(geo_subset) == 1 && tolower(geo_subset) == "all") {
    geo_string <- "*"
  } else {
    geo_string <- paste(geo_subset, collapse = ",")
  }

  ### build the URL and query the API ###
  vars_string <- paste(c(num_vars, cat_vars), collapse = ",")
  url <- paste0("https://api.census.gov/data/",
                year,
                "/acs/acs1/pums?get=",
                vars_string,
                "&for=", tolower(geo_level), ":", geo_string,
                "&key=",
                api_key)
   
  data_rsp <- GET(url)
  data_all_tibble <- helper_tibble(data_rsp)
  return(data_all_tibble)
 }

Next we convert the numeric variables into the right types, since every column currently comes back from the API as text. Most of them (AGEP, GASP, GRPIP, JWMNP, and PWGTP) only need as.numeric(). The two time variables, JWAP (time of arrival at work) and JWDP (time of departure for work), are harder because the API returns a code instead of a time. For example, a JWAP code of 1 means “12:00 a.m. to 12:04 a.m.” The project asks for the midpoint of each time range, so that code should become 00:02:00, and any code meaning “N/A” (such as people who don’t commute) should become NA.

The project instructions allowed using an LLM for this part, and I used one to help write the helper_time() function below.The function looks up each code’s label in the variable values I saved in the .rds file, splits the label into a start and end time, and returns the time halfway between them. I then use a for loop in get_census_data() that sends JWAP and JWDP through this helper and converts the other numeric variables with as.numeric().

Note : The helper_time() function needs to work with times, so the LLM suggested using the following two packages: lubridate, which reads text like “12:00 am” as a time, and hms, which stores the final result as just a time of day (like 00:02:00) without a date attached.

# helper: turn time codes into the midpoint time of each range
helper_time <- function(codes, item_lookup) {
  labels <- unlist(item_lookup)
  time_labels <- unname(labels[match(as.numeric(codes), as.numeric(names(labels)))])
  time_labels[grepl("N/A", time_labels)] <- NA
  time_labels <- gsub("\\.", "", time_labels)
  start <- parse_date_time(sub(" to .*", "", time_labels), "I:M p", quiet = TRUE)
  end <- parse_date_time(sub(".* to ", "", time_labels), "I:M p", quiet = TRUE)
  midpoint <- start + (end - start) / 2
  secs <- hour(midpoint) * 3600 + minute(midpoint) * 60 + second(midpoint)
  return(hms(seconds = secs))
}

Next we need to turn the categorical variables into labeled factors. Right now they come back from the API as codes, so SEX shows 1 or 2 and state shows a number like 37, which isn’t very readable. The variable values I saved in the .rds file already list what each code means. I took inspiration from the helper_time function and came up with a simpler helper_factor() function that uses the saved variable value to replace each code with its label (for example, SEX 2 becomes “Female” and state 37 becomes “North Carolina/NC”). One problem is that codes aren’t always written the same way in the data and in the saved variable value, for example “1” versus “01”.

To solve this issue the helper_factor function removes leading zeros from both the data and the saved variable value before matching them. I also apply this to the geography column so the state, region, or division names are readable.

Lastly I add the “census” class to the tibble, which will let me write custom summary() and plot() functions later in the project.

# helper: turn categorical codes into a factor with labels
helper_factor <- function(codes, item_lookup) {
  labels <- unlist(item_lookup)

  # remove leading zeros from number codes so "01" and "1" match
  clean_codes <- function(x) {
    ifelse(grepl("^[0-9]+$", x), as.character(as.numeric(x)), x)
  }

  return(factor(clean_codes(codes),
                levels = clean_codes(names(labels)),
                labels = unname(labels)))
}

Combining Years

Next we need to combine multiple years of survey data into one tibble. The get_census_multi() function calls get_census_data() once for each year the user asks for, adds a year column so we can tell the rows apart, and stacks the results with bind_rows(). Since get_census_data() already checks each year, this function doesn’t need its own checks. I make year a factor because it will be treated as a categorical variable in the summaries later, and I add the “census” class again at the end, because combining tibbles can drop it.

get_census_multi <- function(years = c(2023, 2024),
                             num_vars = c("AGEP", "PWGTP"),
                             cat_vars = "SEX",
                             geo_level = "State",
                             geo_subset = NULL) {

  # call the single-year function once for each year and tag the rows
  year_data <- lapply(years, function(y) {
    one_year <- get_census_data(year = y,
                                num_vars = num_vars,
                                cat_vars = cat_vars,
                                geo_level = geo_level,
                                geo_subset = geo_subset)
    one_year$year <- y
    return(one_year)
  })

  # stack the years into one tibble
  combined <- bind_rows(year_data)

  # treat year as a category (needed for the summaries and plots later)
  combined$year <- factor(combined$year)

  # make sure the combined tibble still has the census class
  class(combined) <- unique(c("census", class(combined)))
  return(combined)
}

Part 2

Writing Generic Functions for Summarizing

In this section we write generic functions for summarizing our data. In R, functions like summary() and plot() are generic, which means they check an object’s class and then use the matching version of the function. For example, plot() calls UseMethod(“plot”), so a data frame gets a different plot than a function does. This is important to mention since we added the “census” class to our tibbles, we can finally use this to write our own summary.census() and plot.census() functions, and R will use them automatically whenever summary() or plot() is called on census data which is pretty neat.

Numeric Summaries

Here we write a custom summary function for census tibbles. Since each row stands for a different number of people (the PWGTP weight), regular summaries would treat every row as one person and give misleading results. The summary.census() function calculates weighted means and standard deviations for the numeric variables and weighted counts for the categorical variables. By default it summarizes every numeric variable except PWGTP and the time variables, and every categorical variable including year, but the user can choose specific variables instead.

The summary.census function is written with dplyr, using group_by() and summarize() for the weighted counts, and .data[[v]] to refer to a column whose name is stored in a variable inside the loops.

summary.census <- function(object, num_vars = NULL, cat_vars = NULL, ...) {
  time_vars <- c("JWAP", "JWDP")

  # default: all numeric columns except PWGTP and the time variables
  if (is.null(num_vars)) {
    num_cols <- object |>
      select(where(is.numeric)) |>
      names()
    num_vars <- setdiff(num_cols, c("PWGTP", time_vars))
  }

  # default: all factor columns (categorical variables, geography, and year)
  if (is.null(cat_vars)) {
    cat_vars <- object |>
      select(where(is.factor)) |>
      names()
  }

  results <- list()

  # weighted mean and standard deviation for each numeric variable
  for (v in num_vars) {
    results[[v]] <- object |>
      filter(!is.na(.data[[v]])) |>
      summarize(weighted_mean = sum(.data[[v]] * PWGTP) / sum(PWGTP),
                weighted_sd = sqrt(sum(.data[[v]]^2 * PWGTP) / sum(PWGTP) - weighted_mean^2))
  }

  # weighted counts for each categorical variable
  for (v in cat_vars) {
    results[[v]] <- object |>
      group_by(.data[[v]]) |>
      summarize(weighted_count = sum(PWGTP))
  }

  return(results)
}

Graphical Summaries

Next we write a custom plot function for census tibbles. The plot.census() function requires the user to choose one categorical variable (which can include year) and one numeric variable, and it creates a boxplot of the numeric variable for each level of the categorical one. Inside aes() we set weight = PWGTP so each row counts as the number of people it represents, just like in the summary function. Since the variable names are passed in as text, we use get() to look up the matching columns

plot.census <- function(x, cat_var, num_var, ...) {

  # both variables are required
  if (missing(cat_var) || missing(num_var)) {
    stop("you must give one categorical variable and one numeric variable")
  }
  if (length(cat_var) != 1 || length(num_var) != 1) {
    stop("you can only give one categorical and one numeric variable")
  }

  # check the variables exist and have the right types
  if (!(cat_var %in% names(x)) || !is.factor(x[[cat_var]])) {
    stop(paste(cat_var, "is not a categorical variable in this data"))
  }
  if (!(num_var %in% names(x)) || !is.numeric(x[[num_var]])) {
    stop(paste(num_var, "is not a numeric variable in this data"))
  }

  # weighted boxplot of the numeric variable for each category
  ggplot(x, aes(x = get(cat_var), y = get(num_var), weight = PWGTP)) +
    geom_boxplot() +
    labs(x = cat_var, y = num_var,
         title = paste("Weighted boxplot of", num_var, "by", cat_var))
}

Rethinking who to include

As I looked at the boxplots, it bothered me that they weren’t really showing the trend I expected, since there should have been a bigger difference in who went to work in 2021, during the pandemic, compared to 2024. Then I remembered that at the very beginning of this investigation, I set an exclusion rule so that only people with a commute time above zero were included in my analysis. In doing this, I actually ended up excluding everyone working from home. My reason for the rule was logical, since I didn’t want to include children or retired people and make the results unclear. After rethinking it, I decided an age range would be a better way to handle this problem, so below I select only people between the ages of 25 and 64. I also add a new categorical variable, commute_status, that labels each person as commuting or not, so the summary function can count both groups. There is still the problem that some people in this age range are unemployed, and I think it is fair to treat this as an inherent limitation of the available data.

# working-age adults, keeping people with a commute time of 0
working_age <- nc_commute |>
  filter(AGEP >= 25, AGEP <= 64) |>
  mutate(commute_status = factor(ifelse(JWMNP > 0, "Commutes", "Does not commute")))

# share commuting in each year
summary(filter(working_age, year == "2021"), num_vars = "JWMNP", cat_vars = "commute_status")

This shows a much clearer change. In 2021, about 57% of working-age adults in North Carolina commuted to work, compared to about 63% in 2024. The number of working-age adults who didn’t commute dropped by about 229,000, even though the working-age population grew over the same period. As for the average commute, it increased from about 14.6 to 16.8 minutes, and the boxplot shows the median moving from about 10 to 12 minutes. One limitation is that a commute time of 0 also includes people who aren’t working at all, not only people working from home, so this measures commuting versus not commuting rather than remote work directly. Still, the drop in non-commuters fits with many people returning to in-person work after the pandemic.

Conclusion

In this project, I wrote functions to query the Census PUMS API, clean and label the results, combine multiple years, and summarize and plot the data while accounting for the survey weights. Writing the functions turned out to be a lot more challenging than I expected when I started. It was only when I began building them and trying to run them that I found out how hard it can be to get all the parts to fit together and work.

Interestingly enough, I had a similar experience with the investigation. When I looked at commuting in North Carolina, I expected an obvious result: a big increase in commuters in 2024 compared to 2021, during the pandemic. But just like building the functions, the analysis turned out to have more layers than I first thought. I first compared only people who commute, to keep my data clear, and found little change in a typical commute (a median of about 20 minutes in both years). When I included people who don’t commute, the change was much clearer: the share of working-age adults commuting rose from about 57% in 2021 to 63% in 2024. However, this came at the cost of some clarity, since I am now including people who are unemployed or not working for other reasons. This showed me how much the inclusion and exclusion rules used in an analysis can affect the results. More generally, I think the biggest takeaway from this project for me is to not judge the complexity of a task by how simple it sounds at first. Because when dealing with data the challenges really come up once you start working through the problem.
